Мы будем решать это задание "в лоб". С одной стороны, у вас это отнимет несколько лишних минут, с другой, вы не устанете от "заметим" и "очевидно, что,,," и не сделаете ошибок по невнимательности. # Пример 1)

### Задание 60248

![[_Resours/Pasted image 20241031130902.png]]

Итак, перво-наперво, мы импортируем [[Предметы/Инфушечка/Истинный фундамент/04 Функции/04.8 Стандартная библиотека|библиотеку `turtle`]]. Делается это вот такой командой:

```python
from turtle import *
```

Почему именно так? Ведь обычно [[Предметы/Инфушечка/Истинный фундамент/04 Функции/04.8 Стандартная библиотека|библиотеки импортируются]] как-то так:

```python
import turtle
```

Разница в том как мы будем обращаться к классам и методам. Во втором случае модуль подключается под именем turtle и перед использованием команд каждый раз требуется писать, что это именно модуль, а не рандомный набор букв:

```python
import turtle
turtle.forward(100)
turtle.left(90)
```

В первом же случае мы импортируем все [[Предметы/Инфушечка/Истинный фундамент/04 Функции/index|функции]] и классы из модуля turtle в область видимости, что позволяет нам обращаться с ними без префикса turtle:

```python
from turtle import *
forward(100)
left(90)
```

Что гораздо удобнее.

(Небольшое замечание: такой подход действительно быстрее и удобнее, но иногда может приводить к конфликтам имен, если в программе уже есть [[Предметы/Инфушечка/Истинный фундамент/04 Функции/index|функции]] или [[Предметы/Инфушечка/Истинный фундамент/03 Строки, переменные и типы данных/03.5 Что такое переменная|переменные]] с такими же именами. На ЕГЭ этого бояться не стоит, но это стоит держать в голове на случай иных импортов, если они понадобятся)

Далее нам нужно задать несколько базовых для работы программы параметров:
1) Отрисовка
2) Размер экрана
3) Коэффициент расширения
4) Разметку
5) Команда выхода по клику

По порядку:

1) Отрисовка - это то, как быстро черепашка будет рисовать. Задается с помощью команды tracer(0) - мгновенная отрисовка либо же speed(x) - скорость рисования черепашки. С tracer не рекомендую экспериментировать, программа может начать выдавать фигню, лучше всегда ставить 0, а вот speed - это буквально скорость рисования. Команда может принимать на вход любые числа и чем число больше - тем больше скорость рисования. Выглядит это так:

2) Размер экрана - это то, сколько на сколько пикселей будет на экране, который откроется в момент выполнения программы. Обычно ставят где-то 1500х1500 пикселей для удобства. Если изображение будет получаться маленьким - мы отредачим его с помощью коэффициента расширения.

3) Коэффициент расширения - это числовой [[Предметы/Инфушечка/Истинный фундамент/04 Функции/04.11 Параметры функций|параметр]], влияющий на размер изображения. Т.е. буквально, если такого коэффициента нет или он равен 1, то изображение будет получаться, например, 100х50 пикселей прямоугольником, а если он равен 10, то 1000х500 прямоугольником. Нужен исключительно для нашего удобства, чтобы было хорошо видно что и как мы делаем.

4) Разметка - это сетка и точки на координатной плоскости рисунка. Да, у рисунка есть невидимая [[Предметы/Инфушечка/Истинный фундамент/02 Минимальный Python/02.6 Числа и арифметика|координатная плоскость]], (0, 0) которой находится там же, где спавнится черепашка. Разметка нужна, чтобы иметь возможность считать те точки, о которых пишут в заданиях.

5) Команда выхода по клику - это вот такая штучка:

```python
exitonclick()
```

Нужна для того, чтобы программа корректно могла завершить работу. Благодаря ней вы можете просто кликнуть по экрану где ползает черепашка и завершить выполнение программы.

Со всеми подготовительными финтифлюшками программа будет выглядеть так:

```python
from turtle import * #Импорт бибы turtle
#tracer(0)
speed(2) #Скорость отрисовки
screensize(1500,1500) #Размер экрана
k = 1 #Коэффициент расширения
lt(90) #Изначально черепашка стоит ебалом в пол (направо), ее надо повернуть немного

for x in range(-25, 25): #Эти циклы нужны для разметки, чтобы нарисовать красные точки, значения подбираются чисто на глаз
    for y in range(-25, 25):
        goto(x * k, y * k)
        dot(3, 'red')
exitonclick()
```

Ну и помимо подготовительных финтифлюшек надо написать еще и саму программу. Тут дело не хитрое - надо просто слово в слово переписать че написано в условии. Будем использовать следующие команды и их сокращения:

Эти команды даже сверх нужного вам. В основном, используются стандартные команды передвижения вперед-назад, влево-вправо, повороты, поднятие и опускание пера, скорость и `goto`. Напишем код, который есть в условии с помощью представленных команд:

```python
for n in range(2): #Алгоритм из условия, строка 1
    fd(10*k)
    rt(90)
    fd(18*k)
    rt(90)

up() #Алгоритм из условия, строка 2

fd(5*k)  #Алгоритм из условия, строка 3
rt(90)
fd(7*k)
lt(90)

down() #Алгоритм из условия, строка 4

for n in range(2): #Алгоритм из условия, строка 5

    rt(90)
    fd(7*k)
    rt(90)

up() #На будущее, чтобы черепашка не чертила пока рисует разметку
```

# Изменения 2026 года

Черепашка - одно из тех заданий, которые претерпели изменения на ЕГЭ 2026. Тенденция, к сожалению, в сторону усложнения. Например, есть такое условие:

![[Pasted image 20260826163512.png]]

Если решать по шаблону, то решается оно вот так:

```python
# №28927

from turtle import *

tracer(0)
screensize(3000, 3000)
k = 5
lt(90)

for i in range(6):
    fd(71 * k)
    rt(90)
    fd(73 * k)
    rt(90)

up()
fd(18 * k)
rt(90)
fd(22 * k)
lt(90)

down()
for i in range(6):
    fd(45 * k)
    rt(90)
    fd(58 * k)
    rt(90)

up()
for x in range(-10, 100):
    for y in range(-10, 90):
        goto(x * k, y * k)
        dot(2, 'red')

exitonclick()

# Ответ: 2392
```

![[Pasted image 20260826163940.png]]

Это очень большие фигуры.

> [!danger]
> Именно в этом и заключается основная проблема новых номеров черепашки - большие цифры усложняют решение, поскольку вручную уже очень легко ошибиться с подсчетом.

Глобально, есть несколько выходов из этой ситуации:

1) На морально-волевых продолжать считать руками
2) Немного модифицировать координатную сетку, добавить несколько точек-ориентиров для удобства
3) Графический способ: проследовать за алгоритмом на бумаге, начертить то же самое и посчитать что требуется
4) Звездный путь: придумать универсальный код для этого тоже

Первый вариант не рассматриваем, поговорим о вариантах 2, 3 и 4.

Здесь будет только один такой пример с большими числами, хотя их в 2025-2026 годах было довольно много. В целом, просто решайте графическим способом и проблем знать не будете, господа хорошие.

### Модификация координатной сетки

Собственно, выглядит она как-то так:

```python
# Было
'''
for x in range(-10, 100):
    for y in range(-10, 90):
        goto(x * k, y * k)
        dot(2, 'red')
'''
# Стало
for x in range(-10, 100):
    for y in range(-10, 90):
        goto(x * k, y * k)
        if (x * k) % 10 == 0 and (y * k) % 10 == 0:
	        dot(5, 'blue')
        else:
	        dot(2, 'red')
```

Что это меняет? Если раньше мы путались в огромном кол-ве красных точек, то теперь у нас вот такая ситуация:

![[Pasted image 20260826164719.png]]

Как видно, каждая синяя точка отмечает каждую пятую точку. Можно добавить еще ориентиров, если хотите, тут приветствуются эксперименты. Считать стало чуть легче. Можно прикинуть, что прямоугольник пересечения имеет стороны `52` и `46` и таким образом ответ `2392`.

> [!warning] Внимание
> В этом способе ошибиться все еще довольно легко.

### Способ графиком и калькулятором

> [!tip] Совет
> Графический способ - самый универсальный и простой способ. Потому, что фигуры не обязательно могут быть прямоугольниками, не обязательно с параллельными осям сторонами, не обязательно повороты под 90 градусов. Никогда не знаете степень ебанутости экзаменаторов. Из этого вытекают ограничения Звездного пути, о которых чуть позже расскажу.

В этом случае здесь нам понадобятся наши ручки и тетрадка. Собственно, нужно проследовать за алгоритмом и буквально на бумаге начертить то, что чертит он. Сделаем это.

### Звездный путь

Этот код имеет следующие ограничения:

1) Он сработает только для прямоугольников (повороты должны быть 90 градусов)
2) Он сработает только если пересечение действительно есть

Итак, код:

```python
p, d, pen, figs = 0, 1j, 1, [[0]]        # позиция, направление, перо, фигуры

def fd(n):
    global p
    p += d * n
    if pen: figs[-1].append(p)

def bk(n): fd(-n)

def rt(a):
    global d
    d *= (-1j) ** (a // 90)

def lt(a): rt(-a)

def up():
    global pen; pen = 0

def down():
    global pen; pen = 1; figs.append([p])

def box(f):
    return (min(z.real for z in f), max(z.real for z in f),
            min(z.imag for z in f), max(z.imag for z in f))


# ---------- программа из условия (переписываем слово в слово) ----------
for i in range(6):
    fd(71); rt(90); fd(73); rt(90)

up()
fd(18); rt(90); fd(22); lt(90)

down()
for i in range(6):
    fd(45); rt(90); fd(58); rt(90)
# -----------------------------------------------------------------------

(x1, x2, y1, y2), (X1, X2, Y1, Y2) = map(box, figs)
w = min(x2, X2) - max(x1, X1) + 1
h = min(y2, Y2) - max(y1, Y1) + 1
print('пересечение:', int(w * h))
print('объединение:', int((x2-x1+1)*(y2-y1+1) + (X2-X1+1)*(Y2-Y1+1) - w*h))
```

>
> Комплексное число выглядит так:
>

> ```text

> ```

>

> ```
>

>

> ---
>
> ```python
> pen = 1
> ```
>

>

>

>

>

>
> Изначально:
>
> ```python
> figs = [[0]]
> ```
>
> То есть есть первая фигура, и её первая точка — `0`, то есть `(0, 0)`.
>
> ---
>
> ```python
> def fd(n):
> ```
>

>
> Она будет двигать черепаху вперёд на `n`.
>
> ---
>
> ```python
>     global p
> ```
>
> Говорим Python:
>
> > внутри функции я буду менять [[Предметы/Инфушечка/Истинный фундамент/03 Строки, переменные и типы данных/03.5 Что такое переменная|глобальную переменную]] `p`.

>
> ---
>
> ```python
>     p += d * n
> ```
>
> Двигаем черепаху.
>
> `d` — направление.
>
> `n` — расстояние.
>
> Например:
>
> ```python
> d = 1j
> n = 71
> ```
>
> Тогда:
>
> ```python
> p += 1j * 71
> ```
>
> То есть черепаха поднимается вверх на 71.
>
> Если направление будет вправо:
>
> ```python
> d = 1
> ```
>
> то:
>

> ```
>

> ---
>

>
> Например:
>
> ```python
> figs = [[0, 71j, 73+71j]]
> ```
>
> Тогда:
>
> ```python
> figs[-1]
> ```
>
> это:
>
> ```python
> [0, 71j, 73+71j]
> ```
>
> То есть последняя текущая фигура.
>
> А:
>
> ```python
> append(p)
> ```
>
> добавляет текущую позицию в [[Предметы/Инфушечка/Истинный фундамент/07 Коллекции/07.1 Списки|список]] точек.

>

> def bk(n): fd(-n)
> ```
>

> > пройти назад на `n` — это то же самое, что пройти вперёд на `-n`.
>

>
> ```python
> bk(10)
> ```
>
> это:
>
> ```python
> fd(-10)
> ```
>
> ---
>
> ```python
> def rt(a):
> ```

>
> ---
>
> ```python
>     global d
> ```
>
> Будем менять направление `d`.
>
> ---
>
> ```python
>     d *= (-1j) ** (a // 90)

>
> ```text
> 90, 180, 270, 360
> ```
>

>
> Потому что:
>
> ```python
> a // 90
> ```
>
> считает, сколько раз надо повернуться на 90 градусов.
>
> Например:
>
> ```python
> 90 // 90 = 1
> 180 // 90 = 2
> 270 // 90 = 3
> ```
>

>
> ```python
> -1j
> ```
>
> поворачивает направление на 90° вправо.
>
> Пример.
>

> ```python
> d = 1j
> ```

> ```

>
> ```python

>

>

> ```
>
> Правая граница пересечения:
>
> ```python
> min(x2, X2)
> ```
>
> То есть:
>
> ```python
> min(73, 80) = 73
> ```
>
> Количество целых `x` от 22 до 73 включительно:
>
> ```python
> 73 - 22 + 1 = 52
> ```
>
> Вот поэтому в коде:
>
> ```python
> w = min(x2, X2) - max(x1, X1) + 1
> ```
>
> `+1` нужен потому, что границы учитываются.
>
> Например, от 1 до 3 включительно есть три числа:
>
> ```text
> 1, 2, 3
> ```
>
> А не два.
>
> ```python
> 3 - 1 = 2
> ```
>
> Поэтому нужно:
>
> ```python
> 3 - 1 + 1 = 3
> ```
>
> ---
>
> ```python
> h = min(y2, Y2) - max(y1, Y1) + 1
> ```
>
> То же самое, но по высоте.
>
> Первая фигура:
>
> ```text
> y от 0 до 71
> ```
>
> Вторая фигура:
>
> ```text
> y от 18 до 63
> ```
>
> Пересечение:
>
> ```text
> y от 18 до 63
> ```
>
> Количество целых `y`:
>
> ```python
> 63 - 18 + 1 = 46
> ```
>
> ---
>
> ```python
> print('пересечение:', int(w * h))
> ```
>
> Печатаем количество точек в пересечении.
>
> ```python
> w = 52
> h = 46
> ```
>
> Значит:
>
> ```python
> 52 * 46 = 2392
> ```
>
> ---
>
> ```python
> print('объединение:', int((x2-x1+1)*(y2-y1+1) + (X2-X1+1)*(Y2-Y1+1) - w*h))
> ```
>
> Здесь считается объединение двух прямоугольников.
>
> Формула:
>
> ```text
> объединение = первая фигура + вторая фигура - пересечение
> ```
>
> Почему надо вычитать пересечение?
>
> Потому что при сложении первой и второй фигуры общая часть считается дважды.
>
> Например:
>
> ```text
> первая фигура содержит пересечение
> вторая фигура тоже содержит пересечение
> ```
>
> Значит, если просто сложить:
>
> ```text
> пересечение посчитали два раза
> ```
>
> Нужно один раз убрать.
>
> ---
>
> ```python
> (x2-x1+1)*(y2-y1+1)
> ```
>
> Количество целочисленных точек в первой фигуре.
>
> Для первой:
>
> ```text
> x от 0 до 73 → 74 значения
> y от 0 до 71 → 72 значения
> ```
>
> Значит:
>
> ```python
> 74 * 72
> ```
>
> ---
>
> ```python
> (X2-X1+1)*(Y2-Y1+1)
> ```
>
> Количество целочисленных точек во второй фигуре.
>
> Для второй:
>
> ```text
> x от 22 до 80 → 59 значений
> y от 18 до 63 → 46 значений
> ```
>
> Значит:
>
> ```python
> 59 * 46
> ```
>
> ---
>
> ```python
> - w*h
> ```
>
> Вычитаем пересечение, которое было посчитано два раза.
>
> ---
>
> Итого код печатает:
>
> ```text
> пересечение: 2392
> объединение: 5640
> ```
