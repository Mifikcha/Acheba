# Пример 1)

![[_Resours/Pasted image 20241005103829.png]]

Согласно условию, в пароле могут быть использовано 26 символов. Известно, что с помощью N бит можно закодировать $2^N$ различных вариантов. Поскольку 24 < 26 < 25, то для записи каждого из 26 символов необходимо 5 бит.

Для хранения всех 10 символов номера нужно 10 · 5  =  50 бит, а так как для записи используется целое число байт, то берём ближайшее не меньшее значение, кратное восьми, это число 56  =  7 · 8 бит (7 байт).

Для хранения всех сведений о 50 пользователях используется 50 · 7  =  350 байт, то есть для хранения данных о 50 пользователях необходимо выделить 350 байт.

**_Ответ:_** 350

![[_Resours/Pasted image 20241005104740.png]]

При кодировании k бит позволяют кодировать 2k символов. Заметим, что $2^4<22<2^5$, поэтому для кодирования 22-символьного алфавита требуется 5 бит. Для хранения 13 символов требуется 13 * 5 = 65 бит.

Минимальное число бит, необходимое для кодирования числа, не превышающего 1000, равно 10 битам. Следовательно, для хранения двух таких чисел потребуется 20 бит. Личный код и код подразделения записываются подряд и вместе занимают минимально возможное целое число байт. Минимальное количество байт, вмещающее в себя 85 бит,  — 11 байт. Всего на пропуске хранится 32 байт данных. Значит, для хранения дополнительных сведений о сотруднике отводится 32 байта − 11 байт  =  21 байт данных.

**_Ответ:_** 21.

# Пример 7)

![[_Resours/Pasted image 20260827161858.png]]

Начнем с памяти. У нас есть `65 536` серийных номеров, и всего потребовалось **не менее 7 Мбайт**. Переведем в байты:

```text
7 * 1024 * 1024 = 7 340 032 байт
```

Теперь узнаем, сколько байт минимум приходится на один серийный номер:

```text
7 340 032 / 65 536 = 112 байт
```

То есть каждый серийный номер должен занимать **не менее 112 байт**.

Длина номера - `105` символов. Пусть на один символ нужно `i` бит. Тогда один номер весит:

```text
105 * i бит
```

Проверяем:

```text
i = 8: 105 * 8 = 840 бит = 105 байт
```

Мало, потому что нужно хотя бы `112` байт.

```text
i = 9: 105 * 9 = 945 бит
945 / 8 = 118,125 байт → 119 байт
```

Подходит.

Значит, на символ нужно `9` бит. Тогда мощность алфавита должна быть больше, чем покрывают `8` бит:

```text
2^8 = 256
```

Минимальная возможная мощность алфавита:

```text
256 + 1 = 257
```

**Ответ: 257**

# Пример 8)

![[_Resours/Pasted image 20260827163443.png]]

Сначала найдем размер алфавита:

```text
10 цифр + 26 букв + 8164 символа = 8200 символов
```

Подбираем количество бит на символ:

```text
2^13 = 8192
```

Не хватает.

```text
2^14 = 16384
```

Хватает. Значит, каждый символ кодируется `14` битами.

Теперь память:

```text
156 Кбайт = 156 * 1024 = 159 744 байт
```

Есть `835` серийных номеров. Нужно, чтобы памяти требовалось **более 156 Кбайт**.

Проверим длину `109`:

```text
109 * 14 = 1526 бит
1526 / 8 = 190,75 байт → 191 байт
835 * 191 = 159 485 байт
```

Это меньше, чем `159 744`, не подходит.

Проверим длину `110`:

```text
110 * 14 = 1540 бит
1540 / 8 = 192,5 байт → 193 байт
835 * 193 = 161 155 байт
```

Это уже больше `156 Кбайт`.

**Ответ: 110**

# Пример 9)

![[_Resours/Pasted image 20260827163528.png]]

Размер алфавита:

```text
10 цифр + 62 символа = 72 символа
```

Подбираем количество бит на символ:

```text
2^6 = 64
```

Не хватает.

```text
2^7 = 128
```

Хватает. Значит, каждый символ кодируется `7` битами.

Теперь память:

```text
23 Мбайт = 23 * 1024 * 1024 = 24 117 248 байт
```

Есть `5 895 222` серийных номера.

Проверим длину `4`:

```text
4 * 7 = 28 бит
28 / 8 = 3,5 байт → 4 байта
5 895 222 * 4 = 23 580 888 байт
```

Это меньше `23 Мбайт`, не подходит.

Проверим длину `5`:

```text
5 * 7 = 35 бит
35 / 8 = 4,375 байт → 5 байт
5 895 222 * 5 = 29 476 110 байт
```

Это больше `23 Мбайт`.

**Ответ: 5**
