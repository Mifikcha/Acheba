## Журнал решений

- **2026-08-31**: В попапах Quartz удалять `.breadcrumb-container` и `.note-properties` только из загруженного `Document` в `popover.inline.ts`, не скрывая эти компоненты на самих страницах. Для графа встроенный `.graph-container` оставляет обычное колесо прокрутке страницы и принимает zoom по `Shift + wheel`, а `.global-graph-container` принимает обычный wheel; коэффициент D3 `wheelDelta` держать в `_quartz/scripts/patch-graph.mjs` как `0.325` — ровно на 30% выше прежнего `0.25`.
- **2026-08-09**: Для темы `default` в `@quartz-themes/core` использовать `mode: both`. При `mode: dark` импортированные Obsidian-правила геометрии оборачиваются только в `[saved-theme="dark"]`, поэтому светлая тема получает другой каскад и меняет margin, font-weight, border-radius и размеры компонентов. Hero-заголовок считать от ширины собственного контейнера через `cqi`, а не от viewport; если `.markdown-preview-view` уже начинается с `h1`, скрывать дублирующий Quartz `.article-title`.
- **2026-08-04**: На главной Quartz не использовать старые ссылки вида `./репетиторство-1/...`; актуальные публичные разделы лежат в `./Предметы/шизончик/`, `./Предметы/инфушечка/`, `./Предметы/матанчик/` в исходном Markdown и нормализуются Quartz в URL `./предметы/...`.
- **2026-08-04**: Встроенный граф на главной `Публичный сайт/index.md` использует собственный HTML `data-cfg` и не наследует автоматически `globalGraph` из `_quartz/quartz.config.yaml`. Для главной держать и `.graph-container`, и `.global-graph-container` с `depth: -1`, иначе свернутый граф становится локальным графом `index` и показывает почти только `Hopes and Dreams`.
- **2026-08-04**: Для Quartz Graph View базовым вариантом считать дефолты из документации: local graph `depth: 1`, `scale: 1.1`, `repelForce: 0.5`, `centerForce: 0.3`, `linkDistance: 30`, `fontSize: 0.6`, `opacityScale: 1`, `showTags: true`, `enableRadial: false`; global graph `depth: -1`, `scale: 0.9`, `focusOnHover: true`, `enableRadial: true` при тех же force/font значениях. Не переносить `alphaTarget(...).restart()` в обработчик `drag`: с условием `i.active || ...` симуляция может не перезапуститься и точки перестают видимо перемещаться.
- **2026-08-04**: Если подписи Quartz/Pixi-графа выглядят размытыми после уменьшения `fontSize`, не уменьшать только итоговый размер: Pixi сначала растеризует `Text` в текстуру, а зум потом масштабирует ее. Держать маленький визуальный размер через high-DPI текстуру (`fontSize`/`resolution` выше) и компенсирующий `label.scale`.
- **2026-08-04**: Подписи Quartz-графа управляются не только `fontSize`/`opacityScale` в `quartz.config.yaml` и HTML `data-cfg`, но и minified формулой в `@quartz-community/graph`; устойчивые правки класть в `_quartz/scripts/patch-graph.mjs`, который запускается в `prebuild`/`postinstall`.
- **2026-08-28**: Каждая опубликованная заметка должна быть связана с корнем `Hopes and Dreams` на графе. Поддерживать это одной синтетической runtime-связью в `_quartz/scripts/patch-graph.mjs`, а не массовыми тегами или wiki-ссылками в Markdown: так правило автоматически применяется к новым заметкам и не засоряет их содержимое. Для спокойного TOC держать глубину до `h3`, скрывать заголовки внутри callout/transclude и пункты вида `Пример/Решение/Ответ/Проверка`; смысловые заголовки заметок не удалять.
- **2026-08-28**: В длинной публичной заметке держать не более 10 смысловых пунктов TOC (`h1`–`h3`). Коэффициенты, единицы, шаги решения, частные случаи и повторяющиеся примеры понижать до `h4`: это сохраняет визуальную структуру и старые hash-якоря, но убирает детали из оглавления. Для первого клика TOC не совмещать CSS `scroll-behavior: smooth` с несколькими отложенными `scrollIntoView`: корректирующие проходы должны быть мгновенными, иначе они перезапускают анимацию и первый клик останавливается раньше цели.
- **2026-08-29**: Визуальный эталон публичного графа — локальный Obsidian: маленькие узлы без обводок, линии тоньше пикселя и с низкой базовой прозрачностью, подписи небольшие и скрыты до сильного приближения, без искусственной radial-force. Числа Obsidian нельзя переносить в D3 буквально: сохранять ощущение через Quartz-параметры и проверять полный граф; обязательные синтетические связи с `Hopes and Dreams` компенсировать более слабой link-force и большим link-distance, а не увеличением масштаба узлов.
- **2026-08-04**: Для публичных теоретических заметок `Шизончик` лучше добавлять видимую строку `Связанные темы: [[...]], [[...]].` сразу после frontmatter, если связь не вписывается естественно в абзац. Невидимые Markdown-ссылки вида `[](Репетиторство/...)` не использовать: они не помогают читателю и могут давать неверные slug на сайте.
- **2026-08-04**: В публичном Quartz-контенте не использовать wiki-ссылки с префиксом `Публичный сайт/...`: `_quartz/content` уже указывает на `Публичный сайт`, поэтому такой префикс попадает в slug и создает битые URL вида `/публичный-сайт/...`. Для внутренних ссылок использовать короткие wiki-ссылки от имени заметки или путь внутри content root, например `[[Пояснения к размерностям#ньютон-н|Н]]`.

### Правила properties для учебных заметок

- Для тем учебной программы использовать `type: curriculum_topic`.
- Для физических тем использовать `subject: physics`; для будущих предметов задавать аналогично коротким латинским id (`math`, `informatics`), если пользователь не задаст другой стандарт.
- `topic_id` — стабильный машинный код темы. Для физики формат `PHYS-SECTION-NNN`, например `PHYS-MECH-001`. Не менять `topic_id` при переименовании файла без явного запроса.
- `section` — короткий латинский id раздела. Для физики текущие значения: `reference`, `mechanics`, `molecular_physics`, `electrodynamics`, `quantum_physics`.
- `title` — человекочитаемое название темы на русском, обычно совпадает с названием заметки без `.md`.
- `order` — последовательный номер темы внутри своего `section`: `1`, `2`, `3` и далее без шагов по 10. При добавлении темы в середину раздела перенумеровать порядок внутри раздела, если пользователь не попросит оставить зазоры.
- `duration_lessons` — примерная длительность темы в занятиях; ставить осторожную оценку целым числом, а при сомнении оставлять прежнее значение или `1`.
- `prerequisites` и `next_topics` — YAML-списки `topic_id`. Если зависимости не проработаны, оставлять `[]`, не выдумывать связи.
- `status` описывает готовность заметки как элемента учебной программы: `draft` — черновик/не вычитано; `ready` — можно использовать в программе; `needs_review` — надо пересмотреть; `archived` — устарело и не использовать. По умолчанию для новых или неоценённых материалов ставить `draft`.
- `student_visible` — можно ли показывать ученику. По умолчанию `true` для обычных теоретических тем; `false` для внутренних методических заметок, черновых планов, личных комментариев и служебных файлов.
- `parent_visible` — можно ли показывать родителю. По умолчанию `true` для нейтральных тем программы; `false` для внутренних комментариев, оценок слабых мест конкретных учеников и методических заметок.
- `materials_ready` описывает готовность материалов: `missing` — материалов нет; `partial` — есть основа, но не всё готово; `complete` — тема полностью собрана и проверена. По умолчанию ставить `partial`, если текст заметки уже есть, но качество не проверялось.
- Не добавлять `level` и `difficulty` в учебные темы. Для отбора тем по 9/11 классу, ОГЭ/ЕГЭ и группам использовать отдельные `.base` файлы и Markdown-программы.
