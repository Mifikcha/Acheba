### Токенизация (Tokenization)

**Что это такое?**  
Токенизация — это процесс разбиения текста на минимальные единицы (токены), такие как слова, подслова или символы, с последующим присвоением каждому уникального числового идентификатора из словаря модели.

**Зачем это нужно?**  
Решает проблему представления естественного языка для машин: текст — это строки, а модели работают с числами; токенизация делает текст компактным и обрабатываемым, учитывая морфологию и редкие слова.

**Где и в каких задачах используется?**  
Во всех NLP-задачах: машинный перевод, генерация текста, анализ тональности, чат-боты; ключевой шаг в моделях вроде GPT, BERT, Transformer.

**Как это работает на высоком уровне?**  
Текст разбивается на токены (например, слова или подслова), затем каждый токен сопоставляется с ID из фиксированного словаря; алгоритмы вроде BPE сливают частые пары символов для оптимального словаря.

**Какие есть основные варианты / подтипы?**  
Byte-Pair Encoding (BPE, для подслов), WordPiece (BERT), SentencePiece (независимо от пробелов), Unigram (альтернатива BPE); также простая токенизация на слова/символы.

**Чем это отличается от похожего метода?**  
От стемминга/лемматизации — фокусируется на разбиении для модели, а не на нормализации форм; стемминг упрощает слова, токенизация готовит для эмбеддингов.

**Какие ограничения или минусы?**  
Зависит от корпуса (редкие слова → [UNK]), разные модели имеют разные токенизаторы (несовместимость), может разбивать слова неинтуитивно (например, "unhappiness" → "un", "##happy", "##ness").

**Почему это исторически возникло именно так?**  
В 2010-е с ростом данных и моделей (Sennrich 2016 для BPE в переводе) нужно было справляться с большим словарем без OOV; эволюция от словных словарей к субсловным для редких языков.

**Как это связано с геометрией / векторами?**  
Токены — индексы для lookup в эмбеддинг-матрице; субсловные токены позволяют геометрически комбинировать морфемы в векторном пространстве.

**Как это используется на практике (библиотеки, API)?**  
Библиотеки: Hugging Face Tokenizers (BPE, WordPiece), NLTK/SpaCy (простая); API: OpenAI Tiktoken, Hugging Face Transformers для предобученных токенизаторов.

### Внимание (Attention Mechanism)

**Что это такое?**  
Механизм внимания — это способ модели фокусироваться на релевантных частях входа, вычисляя взвешенные связи между элементами последовательности.

**Зачем это нужно?**  
Решает проблему дальних зависимостей: в последовательностях (текст, речь) слова связаны не только локально, внимание позволяет учитывать весь контекст эффективно.

**Где и в каких задачах используется?**  
Машинный перевод, генерация текста, вопросно-ответные системы, анализ тональности; основа трансформеров, но начиналось в RNN (Bahdanau 2014).

**Как это работает на высоком уровне?**  
Для каждого элемента вычисляются Query (запрос), Key (ключи), Value (значения); сходство Q и K даёт веса, которые применяются к V для агрегации релевантной информации.

**Какие есть основные варианты / подтипы?**  
Additive (Bahdanau), Dot-Product (Vaswani), Multi-Head (параллельные головы), Self-Attention (внутри последовательности), Cross-Attention (между последовательностями).

**Чем это отличается от похожего метода?**  
От свёрток/RNN — глобально учитывает весь контекст (не локально/последовательно), позволяет параллелизацию; RNN забывает дальнее, свёртки — фиксированное окно.

**Какие ограничения или минусы?**  
Квадратичная сложность (O(n²) по длине), требует маскировки для каузальности, может "рассеиваться" на длинных последовательностях без улучшений.

**Почему это исторически возникло именно так?**  
В 2014 (Bahdanau) для улучшения RNN в переводе, где энкодер-декодер нуждался в фокусе; Vaswani 2017 сделал его самодостаточным, избавившись от рекуррентности.

**Как это связано с геометрией / векторами?**  
Q, K, V — проекции в векторное пространство; внимание — softmax косинусного сходства, как взвешенная сумма точек в пространстве.

**Как это используется на практике (библиотеки, API)?**  
Библиотеки: PyTorch nn.MultiheadAttention, TensorFlow tf.keras.layers.Attention; API: Hugging Face Transformers (встроено в модели).

### Трансформеры (Transformers)

**Что это такое?**  
Трансформеры — архитектура на основе внимания, сочетающая self-attention, feed-forward слои и позиционные эмбеддинги для обработки последовательностей.

**Зачем это нужно?**  
Решает проблему последовательной обработки в RNN: позволяет параллельную обработку, захватывая глобальные зависимости без рекуррентности.

**Где и в каких задачах используется?**  
Почти все современные NLP: перевод (оригинал), генерация (GPT), понимание (BERT), мультимодальность (Vision Transformers).

**Как это работает на высоком уровне?**  
Вход → эмбеддинги + позиция → стеки блоков (attention + FFN) → выход; encoder для понимания, decoder для генерации, или комбинация.

**Какие есть основные варианты / подтипы?**  
Encoder-Decoder (оригинал, перевод), Encoder-only (BERT, классификация), Decoder-only (GPT, генерация); улучшения: Longformer, Reformer.

**Чем это отличается от похожего метода?**  
От RNN/LSTM — параллелизм и глобальное внимание вместо последовательного; от CNN — динамические веса вместо фиксированных фильтров.

**Какие ограничения или минусы?**  
Огромное потребление памяти/вычислений (O(n²)), ограниченный контекст (до 128k токенов), требует больших данных для предобучения.

**Почему это исторически возникло именно так?**  
Vaswani 2017 как альтернатива RNN для ускорения (параллелизм на GPU); эволюция от внимания в RNN к чистому вниманию.

**Как это связано с геометрией / векторами?**  
Последовательность — матрица векторов; внимание — геометрические проекции и взвешенные суммы в многомерном пространстве.

**Как это используется на практике (библиотеки, API)?**  
Библиотеки: Hugging Face Transformers (BERT, GPT), PyTorch/TensorFlow встроенные; API: OpenAI GPT, Google BERT-based услуги.
